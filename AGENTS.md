# Rundale Benchmark agent guide

Read docs/specification.md before changing scoring or runtime behavior. Never claim model or judge qualification without its pinned evidence. Native provider APIs only; no OpenRouter. Do not make paid calls in CI. Run `python3 -m unittest discover -s tests -v` before committing and pushing. For site changes also run `pnpm install --frozen-lockfile`, `pnpm run test`, `pnpm run check`, and `pnpm run build` in site/. Changes must go through PR review; do not merge your own PR. Preserve immutable run history, cost reservations, and source attribution. Never commit credentials or private reviewer identifiers.

Build-suite tests must use temporary fixture directories. The suite builder refuses to overwrite a ready manifest; never reset pinned judges or validation evidence to draft while testing. Provisional automated screening permits execution but never establishes human validation.

## Gatekeeper review

Every agent-authored PR uses the [gatekeeper](.agents/skills/gatekeeper/SKILL.md)
in a fresh context, given only the checkout path or PR number and the author's
model family. Never merge your own PR.

Before pushing, run a local pass on the uncommitted or unpushed checkout and
address blocking findings. After required checks pass, run a PR pass; the
independent gatekeeper merges, requests changes, or hands the decision to the
owner. A hand-off does not authorize the author to merge.

Use a reviewer from the other model family. Codex-authored work goes to Claude:

```sh
claude -p --model claude-opus-5-5 "Run the gatekeeper skill on <checkout | PR N>. Author model family: GPT." </dev/null
```

Claude-authored work goes to Codex in a fresh process:

```sh
codex exec -C <checkout> -m gpt-6.1-sol -c model_reasoning_effort=high \
  -o <report file> "Run the gatekeeper skill on <checkout | PR N>. Author model family: Claude." </dev/null
```

Use an isolated worktree for local review if other work might switch the
checkout. Close stdin and inspect the report after completion. Pass the author's
model family privately in the review invocation; do not encode it in attribution
trailers. A change to Gatekeeper or its invocation is always handed to the owner.

## No AI attribution trailers

Do not add AI co-author trailers, signatures, attribution footers, badges, or
"generated by" notices to commits, PR titles or descriptions, issues, comments,
reviews, or other published text. This includes `Co-Authored-By` entries naming
AI models or tools. Preserve genuine human attribution and required source or
license notices. This rule does not remove model identities from benchmark data
or evidence where they are necessary to describe what was evaluated.
